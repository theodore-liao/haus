# Haus decisions

Settled choices for how Haus looks and behaves. Each line was a correction at least once. Check every change against the lines for the pages it touches, and against the whole-app lines, before calling the change done.

## Design system

Sizes, spacing, and placement come from shared styles, not from each page. Use these before writing any `text-*`, padding, or width on a page. If none fits, add a role to `src/app/haus.css` and use it everywhere, rather than styling one page.

- Text roles live at the top of `src/app/haus.css`: page title, display hero (the one number a page is about), display (pills and card metrics), lead (page description), body, table, kicker (uppercase labels, card titles, table heads), and micro (footnotes, chips, axis ticks). Use `.kicker`, `.display-number`, `.supporting-line`, `.footnote`, and `.num` rather than picking a font size.
- Page header: `.page-title`, with the title and description on the left and page actions on the right.
- Card header: `CardHeader row`. The `CardTitle` and search box sit on the left, and date chips, tabs, filters, and action buttons sit on the right.
- Search: `SearchInput` from `src/components/search-input.tsx`. One size, trims on blur. Do not style an `Input` as a search box.
- Buttons: `Button` from `src/components/ui/button.tsx`, with its variants and sizes. Do not build buttons from plain elements.
- Dollar amounts: `Money`, so privacy blur and cents stay consistent. Owners: `OwnerTag`. Named things inside a card: `ObjectTitle`.
- Surfaces: `Card`, `.chart-card`, `.hero-card`, `.pill`, with spacing from `--space-card` and `--space-block`.
- The look is a professional dark blue with depth. Every card uses one surface (`--surface-bg`, `--surface-border`, `--surface-shadow`: lit from the top, a cool edge, a soft shadow). The page's summary card (`.hero-card`) adds a blue glow from the top right and a thin gold-to-blue top edge. Card titles sit a step brighter than body text. The sidebar is its own darker panel, and the current page is lit with a blue wash, an accent bar, and a blue icon. Active chips and choices take a blue tint. Pills carry a faint wash of their accent color. Donut slices have rounded corners and small gaps, and the ring is drawn on whole pixels (its size rounded, its position snapped) so edges stay crisp. Sankey flows fade from pale at the hub to full color at their category.
- Behind the cards, the page has its soft color glows and a fine dot grid that is clearest at the top and fades lower down. Card titles carry a small blue icon (card-icon.tsx), the same for the same title everywhere; Insurance card slots and Insights measure cards, which have their own labels, don't. Only the summary card's own figure is heavier with the sheen; pills inside it keep their plain color and stay on one line, and an odd last pill spans its row. The summary card's figure is larger and heavier, with a faint white-to-blue sheen unless its color means something. Loading shows the common page shape with a soft shimmer; an empty page shows its sidebar icon in a glowing badge over a faint grid.
- Donuts: `AllocationChart` in `src/components/charts.tsx`, with the shared `.legend-row` grid. A page does not get its own legend columns.
- Tables: `.data-table`, where right-aligned figures use `.num` and two-line cells use `.cell-stack`.
- Number inputs: `NumberField` from `src/components/number-field.tsx`, on a `.field-grid`. The label sits above, `$` or `%` sits inside the box, and one line of help or a short error sits below. A choice between a few options is `Segmented` from the same file.
- A tool's answer: `.hero-figure` for its one number, `.meter` for progress, `Callout` (src/components/callout.tsx) for what to do next (green when on track, gold when behind, red when it cannot work, grey for plain information). Gold never stands in for information.
- Dollar amounts inside a sentence use the sans font (`.callout`, `.field-note`, `.prose-num`). Tables and legends keep mono.

## Whole app

- Reference display: 2560×1440 monitor, browser zoom 100%, Windows scale 100%, Haus text size 100%. Also check 1920×1080. Layout is relative; section boxes fill the width without zooming.
- Haus text size 100% equals the old 130%. The slider runs from 75% to 150%, and everything scales with it, including numbers inside donuts.
- Dollar amounts show cents. Do not round to whole dollars. The exception is projections (the Retirement planner's forecasts): they round to what they can claim, like $2.48M or $49,100, with `Money approx`. Real balances and the "?" working keep cents.
- Privacy blur covers dollar amounts only. Counts, dates, rates, and percents stay clear. A blurred figure at a clipped edge (donut legends) is never cut off: the legend gets room on its right while blurring.
- The eye button beside HAUS (and in the phone header) turns the blur on and off.
- Removing a connection, a recurring bill, or an insurance card asks first.
- The built app (`npm start`) is reachable from other computers on the home network on port 80, so both partners can use it on the one household at an address with no port number. Signing in works over plain HTTP there; the login cookie is HTTPS-only only when the request came over HTTPS. After 5 wrong passphrases from one address, or 30 from all addresses together, within 15 minutes, the lock screen refuses tries for 15 minutes and says so.
- The phone bar shows the first three tabs in the sidebar order. The More sheet can pin any tab to the bar.
- Every button looks and acts like a button. It shows the hand cursor on hover, and only the button itself is clickable, not the row around it. The exception is a table whose whole row opens a detail (retirement accounts).

- Tab reaches page content first: a "Skip to content" link comes before the sidebar, and the sidebar's drag handles are skipped by keyboard.
- Clicking outside a popup or modal closes it. Help under a box is one short line at 13px; anything longer goes behind a "?" beside the label (`InfoTip`, or `info` on `NumberField`). Explanations open from a "?" button in a `Popover` (src/components/ui/popover.tsx).
- No horizontal scroll bar on any legend. If content does not fit, make room, except where a card must keep its row height (the Overview Budget card, Month by month, long tables); then its list scrolls inside the card.
- A scroll bar inside a card is thin and faint, firming up on hover, unlike the page's own scroll bar.
- A box that can scroll inside a card never traps the wheel when its content fits: the page scrolls as if the pointer were outside it. A box with more to show scrolls itself first.
- A table row lights up on hover only when clicking it opens something (Transactions, retirement accounts). Rows that open nothing, like Overview's Month by month, holdings, or Goals, stay still.
- Long names in one-line rows end with "…" instead of wrapping to a second line.
- Ownership labels (who owns an account or wallet) are faded subtext beside the name, not part of the same text.
- Labels and help text are short and plain. Say what it does in one sentence. No jargon, no stacked clauses, and no mention of what the app does not do.
- Nothing is hard-coded to a specific merchant, bank, card, ticker, coin, or person. Fixes must work for any household that links its own accounts.
- A new feature that changes how data is treated can be turned off in Settings.
- The repo contains no names, tickers, account details, property details, screenshots, or anything else unique to this household.
- Every page opens with its main summary card at the top. New tools go below it, never above.
- Cards side by side are the same height. If their content differs a lot, stack them instead.
- A card's result is its most prominent element: larger, and colored where color carries meaning (progress, gain, loss). Inputs are quieter and sit in aligned rows on a shared grid.
- Number boxes apply when you press Enter or leave the box, never mid-typing, so results and charts don't jump while you type. No separate apply button and no "Enter to apply" hint. Sliders and switches apply as you move them. Leaving a box by clicking applies it only after that click lands, so the click never misses a control that shifts.
- Numbers inside inputs are formatted with commas and at most two decimals.
- A result that is waiting on an input says which one, beside the result. It never shows $0.00 as if that were the answer.
- Every card answers "what should I do next?" on screen: a next step, a warning, or a clear "you're on track".
- A fix to one chart or page must not change another. Colors, legend layout, and spacing on untouched pages stay the same.

## Charts and donuts

- All donuts share one legend layout. The name is left-aligned in one column, the dollar amount is right-aligned in its own column, and the donut and legend sit centered in the box. This includes the spend donut.
- All donuts use one palette. Every category has a fixed color that stays the same when categories are checked, unchecked, or appear because of a new date range.
- Every donut legend can check and uncheck items, and the donut updates.
- Sankey colors are fixed per category, stay the same across reloads, and are clearly different from each other. Salary is not purple. The Salary bar has no extra "Income" label. Clicking an income portion opens that income breakdown, and clicking a spending portion opens that spending breakdown, even when both are named Other: rows expand to transactions, and a transaction opens the same sidebar as Transactions. The Other window is titled Other income or Other spending. Each bar shows its dollar amount and its share on the bar, as $X (Y.Y%), in the same bold white type as the category name, even when the text runs past the bar. Hovering a bar does not show an amount. The center has no Income label. Shares are of income on the left, and of spending plus what was saved on the right. To savings/investments (named that way, since it covers both) has no breakdown. When spending exceeds income there is no From savings bar: the right side is just the spending bars.
- Sankey names and amounts are regular weight, white, and slightly larger than body chart text. The Sankey works on mobile.
- A transaction relabelled as income keeps its source name after Plaid drops it and only the saved copy is left; a relabelled paycheck stays Salary.

## Date chips and search

- Date chips sit at the top right of the section, the same everywhere. One set of chips per view.
- Month chips cover exactly that calendar month, with no day from the prior month.
- Transactions offers the three most recent months, then 1M, 3M, 6M, 1Y, and All. Cashflow, spending, and transactions open on the current month. Settings can switch that default to the previous month. It is separate from the chart window.
- Scrolling to "Show more" in Transactions un-highlights the date chips once clicked.
- Stocks and crypto gainers and losers default to 1W. The default is set in Settings.
- Search bars sit at the top left, look identical everywhere (holdings, trades, crypto, transactions), and never cover a section title. Action buttons (Add connection, Add manual entry, Reset filters) stay on the right.
- Search trims leading and trailing spaces and matches every text field except dates.
- Searching Transactions looks through every transaction, not only the chosen chip, and the list scrolls through every match with no "Show more". Only the rows on screen are drawn. The chips un-highlight while searching; picking one narrows the search to that window.
- Row filters have Apply and Cancel at the bottom right.

## Overview

- Pills are Investments (every investment account, including crypto and brokerage cash), Cash, Property (homes, vehicles, and other non-cash assets), and Liabilities (total debt). They add up to household net worth.
- The four pills sit inside the right side of the Household net worth box. Day, week, and month change live in that box.
- Month-by-month shows every complete month plus the current one. Older months appear only when stored transaction history covers the whole month.
- Overview order: the net worth summary, Cashflow, Net worth / allocation, then Budget beside Month by month at half width each. On a wide screen those two are the same height as the Net worth and Allocation cards above them.
- Budget (formerly Needs attention) opens with an On track / Over pace / Over budget chip from a month-end estimate. For each category, the estimate is spent so far plus the daily rate of what's left after one-offs (a single charge of at least half that budget) for the days remaining. Under it is one bar per budget with a tick at today's pace. Each row's Dismiss hides it until next month (stored as a setting) and shows a "Hidden until next month" toast with Undo; a failed save shows an error toast. A long list scrolls inside the card, with a fade at the bottom while more rows are below. Dollar amounts in its sentences use the sans font. The only other thing it shows is a one-line relink notice; sync failures and other app-side problems never appear there. With no budgets it links to Spending's Budget card.
- The Net worth chart shows the change over the chosen range above the chart. Its axis fits the data rather than starting at zero, so the movement is visible. Month by month's Rate has no plus sign. Net and Split chips sit beside the range chips; Split draws assets, liabilities, and net worth.
- Cashflow is one card with its date chips in the header, the Income, Spending, and Net Movement figures, then the Sankey.
- Month by month has a savings-rate line above the table. The open month is marked "so far". With three or more complete months, the best and lowest months by amount saved are marked. Spend vs last year shows only when the same month a year earlier is on file, and only on very wide screens; Income drops below extra-wide. Phones show Month, Spend, and Saved. On a wide screen Budget and Month by month match the Net worth and Allocation cards, and each list scrolls inside its card with the same thin scrollbar as other cards and a fade at the bottom while more is below. On a narrow screen each list scrolls inside a capped height.

## Spending

- Breakdown's date chips end with a Custom chip: it opens From and To dates (both days included) and, once applied, shows those days ("Jun 3 – Aug 9"). The donut, its legend, the total, and the changes all follow the picked days. Changes compare with the same number of days just before. The Budget scales to the window's share of a year (45 days is about 1.5 monthly budgets).
- A charge can be left out of budgets with "Count toward budget" in its transaction sheet. The switch applies right away. A left-out charge still counts as spending (donut, totals, cash flow) but not on the Budget card, Overview's Budget, or Goals. Its row in Transactions says "not in budget". Exclusions are kept by the bank's transaction id, so they survive the row moving to saved history.
- Spending has two tabs, Breakdown and Recurring. The date chips show on Breakdown only. Recurring is the same panel as on the Transactions page. Refunds lives on Transactions.
- The Spend Category box takes two thirds of the width, and Budget takes one third. The donut is large and has a fixed size that does not shrink when budget rows change. On desktop the Breakdown fits one screen without page scrolling: the donut and its legend grow to fill Spend Category, and a long Budget list scrolls inside its card instead of stretching the row.
- The top of Spend Category shows the checked-category total in the same font as the Overview net worth number, with total spend in smaller grey text directly beneath. There is no separate spending pill.
- Loan payments and Rent and utilities start unchecked.
- "Shopping" is the category name everywhere, not "General merchandise".
- Clicking a donut slice opens a large window. Merchant rows expand only when clicked, and they use the same transactions table as the Transactions page, so edits show everywhere immediately. Amounts there are positive and use the smaller grey sub-line style.
- Budget starts from each category's 3-month average. Rows are added by choosing a category from the dropdown, with no separate Add button. Editing needs an Edit button and a Save button. While editing, the monthly amount is a number box that applies on Enter or when you leave it, and says why when the entry is not a usable dollar amount; bad input is never saved. Removing a row (the X) shows a toast with Undo; a failed save or remove shows an error toast. Each row shows percent used and "$X left" or "$X over" to the cent. The header shows "N days left" in the current month, and the budget scales with the date chip.
- A budget row's swatch and name are a button that opens the same category window as a donut slice (merchants, and the month-by-month chart). On Spending it covers the date chip's window; on Overview it covers the open month, which is what that card measures.
- In the current month, each budget bar has a tick for how much of the month has gone. A bar turns red when over budget and amber (with "ahead of pace") when the share spent is more than 10 points past that tick. Otherwise it keeps the category color.
- The spend donut legend shows each category's change against the earlier period, left of the dollar amount: the month before for a month chip (up to the same day while the month is open), or the same length of time before a rolling chip. Up is red, down is green, and "new" means no spend then. There is no comparison for All, or when stored history does not reach back far enough. A line under the total says what it compares with. Other donuts do not show changes.
- The category window shows that category month by month above the merchants, with a dashed average of the complete months. The open month is faded.

- Date chips show on the Breakdown.
- The Budget card has the anchor `/spending#budget`, which Goals and Overview link to; arriving with that anchor selects the current-month chip so the figures match theirs.

## Transactions

- Tabs are All, Recurring, and Refunds. Date chips show on All and Refunds, not on Recurring.
- Refunds shows the transactions table filtered to refunds in the chosen window, before netting against spending.
- The tabs row has the same height and the same gap to the content below on all three tabs, so switching never moves anything.
- Recurring opens with three pills: Per month · Loan payments, Per month · Bills, Per month · Subscriptions. Below them are three cards of the same height, side by side on wide screens and stacked on phones. Each card has a colored top edge matching its pill, its icon, title, and count, and its rows sorted by yearly amount. An empty card says "None found" instead of disappearing.
- Bills are essential services, often varying with use: utilities, phone and internet, insurance, or any charge whose amount moves. Subscriptions are optional services at a set price. Loan payments come from the loan category.
- Clicking a bill opens the same window as a Sankey slice: every charge from that biller, newest first, with no monthly chart, and a transaction opens the edit sheet. "Restore removed (N)" shows the moment a bill is removed, without a reload. It asks first (the button says Continue), then brings them all back to detection. Its count only includes bills the app would list again; a removed merchant that isn't detected, or one switched off from the edit sheet, isn't counted or restored. Each bill shows its cadence (Weekly, Every 2 weeks, Monthly, Every 2 months, Quarterly, Twice a year, Yearly), its latest charge, and "up from" or "down from" the previous charge when the price moved by at least 2% and 50 cents. Remove asks first. There is no next-due date.
- A charge is recurring only when it lands on a set cadence: weekly, every 2 weeks, monthly, every 2 months, quarterly, twice a year, or yearly. Every gap in the run has to fit a window around that cadence. Visiting the same shop often is not a bill. It takes three charges (four for weekly), or two in bill categories (rent and utilities, loan payments, services, insurance). The run must still be going; a bill more than half a cycle overdue (plus 10 days) drops off. Amounts hold within 25% (10% for a two-charge bill); utilities may vary up to 60%. A stray charge after a steady run doesn't hide it. "Inc", "LLC" and the like don't split one biller. Saved history counts, so yearly bills are found. Loan payments are their own kind (recurring.ts).
- A transaction's edit sheet has a "Recurring charge" switch for charges. Turning it on asks which of Loan payments, Bills, or Subscriptions it counts as and how often it lands, and lists that merchant under them whatever its rhythm ("Added by you"). It applies to every charge from the merchant. Turning it off removes the merchant from Recurring, even one the app detected, and it does not count toward Restore removed.
- Transfers between linked accounts are detected automatically when the same amount leaves one account and lands in another. There is no in/out distinction. It can be turned off in Settings.
- A matched transfer shows its label as small grey text beside the merchant, so row height stays the same. The warning reads: "The same amount landed in another linked account, so this is marked Transfer. If you recategorize, the auto-detected Transfer will be overwritten."
- Recategorizing a matched transfer, including with "Always categorize this merchant this way", applies to every matching transaction and overrides the automatic Transfer.
- Transactions can have a note. A small note icon shows on the row when one exists.
- Merchant logos come from a general source, not a hand-written list of merchants.

- When a merchant logo is missing or is the generic globe, the row shows the merchant's first letter instead.
- Export lives in Settings and asks for a date range from a calendar.

- The row count sits beside the search box and follows the search and filters. Saving a note or category changes only that transaction unless "Always categorize this merchant this way" is switched on. It starts on, and a save that changes only the note leaves other transactions alone. Hiding a merchant asks first.

## Stocks and crypto

- Largest moves on Stocks shows stocks only, and Crypto shows crypto only. Each shows up to seven gainers and seven losers.
- Stocks opens with Market value, its day change, and cost basis and gain, with the last 30 days as a small line (and its change) on the card's right side. No note or warning flags one holding's share of the portfolio.
- Below the summary, By account and Largest moves share one row at equal width, then the holdings. There is no By class card, no separate Value chart, and no dividends card.
- 1W and 1M compare today's price with a close from about that long ago, with a few days of slack for weekends. When stored daily prices do not reach the last few days, they are filled in before those moves are shown, so 1W is never a repeat of 1D.
- Crypto and Stocks 1D/1W/1M are today's quantity × (price now − the close on or before N days ago). Purchase dates never gate them, and a held asset with a price is never blank (worst case a 0 move). The price refresh stores 45 days of closes for every held coin.
- A symbol page's per-account entries leave out anything under $1 (dust); the totals still count it. Opened from Crypto, its back button says Crypto and returns there; from Stocks, it says Stocks. From Crypto it says "coins", shows the share of the crypto total, and titles its table "Holdings by account".
- Stocks and coins share one price history by symbol. A past close more than 10 times above or below today's price belongs to another asset with the same symbol, so the 30-day line and the 1D/1W/1M moves ignore it and hold today's price.
- A symbol page opens with that holding's value, shares, average cost, gain, share of the stocks total, and day change, then its price chart. The chart shows stored closes immediately. Opening a coin then fills past the 45 days kept for the list: a year from the public feed, then older closes from the exchange in stretches short enough for its limit, so 6M, 1Y, and All are not the same line. A Stocks button at the top right goes back.
- A window with price movement always has gainers and losers. Percent changes are sane and never come from a bad price.
- Day change is filled for every holding, including options and manually entered assets. It is computed from quantity and price change when the connection has not refreshed.
- Manual entries show "Last updated" with date and time. Edit and Remove sit at the right end of the account column. Edit reopens the entry window with values filled in, and Add becomes Save.
- The manual entry window clearly separates Ticker + shares from Name + dollar value. Ticker entries take cost per share, and dollar entries take total cost basis.
- Crypto holdings show Cost and Total only once some coin has a cost: a manual entry's own cost, or an average cost per coin entered with the Average cost button on the Holdings card. "Manual Entries" is the name, not "Manual Lots".
- The Crypto summary card is "Crypto value" and covers wallets, brokerage crypto, and manual entries. Its right side shows the last 30 days as a small line: today's quantities at each day's stored close. The page never waits for it; the background price refresh stores 30 days of closes for the largest coins, so the line fills in after a visit. Like Stocks, it shows day change, and cost basis and gain once costs exist, saying how many holdings have a cost.
- Adding a wallet accepts a 0x address only at 40 characters (Ethereum-style) or 64 (Sui), shows the error under the address field, and Remove on a wallet or crypto entry asks first.
- The Crypto page renders from stored prices and never waits on the price feed. After it loads it asks for fresh prices (at most every five minutes) and redraws only if something changed.
- A "Wallets" heading sits above the wallet boxes.
- Crypto wallet boxes are all the same size, have no account-holder box, and can be renamed. The By-asset legend does not show an obtrusive scroll bar.
- Wallets accept Bitcoin, Litecoin, Dogecoin, any EVM address (scanned on Ethereum, Base, Arbitrum, Optimism, Polygon, BNB Chain, Avalanche, and Robinhood Chain), Solana, and TRON, using keyless public APIs, each chain read independently.
- A chain whose explorer refuses server requests (Robinhood Chain's sits behind a bot check) is read straight from its public RPC for the tokens already on file, so the wallet keeps updating. When a chain can't be reached at all, its last balances stay and the wallet says "Couldn't reach <chain>. Showing the last balances found." It never says "No balances found" while balances are on file.

## Retirement, property, insights

- The Retirement summary card shows the retirement total, how many accounts and what was contributed this year, the planner's verdict, leading with the same age as the planner ("On pace to retire at 60, or as early as 53", from the saved planner inputs), and pills for Pre-tax, Roth, HSA, and Child accounts balances (those that hold money).
- Retirement, top to bottom: the Retirement summary card; Retirement Accounts (two thirds) beside Child Accounts (one third), the same height; the Retirement planner last. There is no What money becomes card. There is no donut and no separate Projection card. Birthdates are set in Settings; without them the planner works in years from now.
- LAYOUT (supersedes the placement details below): there is no verdict banner. On screens 1536px and wider, the Retirement number and Yearly saving (Needed vs You save now, the Saving a year box, then the one-line verdict with its ?) sit in the left column, and the retire slider and chart sit in the right column, with the chart growing to the column's height. A plan that can't be worked out still shows its message across the card. Kids' two cost boxes share a row from 1280px, and every child row is one line (name, birth year, remove), including on a phone.
- The Retirement planner is one card with no duplicate inputs. Its verdict ("You can retire at 55 spending $80,000 a year" or "You're about $13,800 a year short…", with what the current saving could do instead behind a ?) sits under the saving bars. Yearly saving: Needed and You save now as two bars on one scale with the gap (ahead or short) underneath, since one only means something against the other. Beside it, the Retirement number, with progress and what it pays for. There is no "What would change it" section. Spend a year tops out at $10,000,000. HSA accounts added by hand have their own Remove button, at the end of the row, which asks first. There are no weak-markets or before-59½ pills on the chart. The whose-age choice ("Ages are") sits in the card header beside Today's/Future dollars. The retire slider sits directly above the chart. On screens 1536px and wider the chart sits beside Saving toward it and the Retirement number, those two fill the chart's height, and the Saving a year box sits in the saving block, on the bars. Every other input sits in one edit area underneath; from 2200px Spend, Assumptions, and Kids sit side by side, and narrower Kids takes the full width under Spend and Assumptions. Kids list two across when there's room. Narrower than 1536px the verdict, the chart, the figures, then the inputs stack, with Spend beside Assumptions from 1280px. The chart plot is a fixed short height. Explanations sit behind a ? (the rest of the verdict, what the number means, how to read the chart, each field's note, and what the children change). The planner card fits one screen on the 2560×1440 desktop. While the planner waits on an input, there are no check pills, and a placeholder says what the chart will show.
- Needed a year is a result, never an input. It compounds at the growth rate net of inflation and is in today's money, so the dollar amount rises with prices. Kid costs above today's (a new child, college) come out of each year's saving, and a child leaving home adds back. Saving it lands exactly on the retirement number at the retire age. One growth rate covers cash and investments, and one tax rate covers withdrawals.
- You save now is regular take-home pay (bonuses dropped) plus RSU vests, minus all current spending, plus retirement contributions and stock-plan (ESPP) purchases, annualised. Vests, spending, retirement contributions, and ESPP purchases are only what landed in the three complete months before this one, times 4 for a year, so a vest in an older month or in the current month never counts. A "?" beside it opens the full working: each paycheck source with its amount and rhythm, the vests in those months with their dates, spending over those months times 4 with the loan payments inside it, contributions in those months times 4, and ESPP purchases the same way. The Saving a year box, beside the saving bars, takes the household's own yearly figure; blank uses the estimate, and the box offers the estimate back.
- Retire at is a slider from the current age plus one to 65. Without birthdates it is "Retire in N years" (1 to 25, so it still ends at 65), the page assumes one fixed age today (40) and says so, and the slider moves only the retirement year.
- The planner chart runs from today to 80 when the money lasts for good, or to the spend-down age. Your path (what you save now) is the solid blue main line with a faint weak-to-strong-markets band; the target path (the least that reaches the number) is gold and dashed. The gap between them is green where you're ahead and red where you're behind. Markers show retiring, the house, other income starting, and Medicare; the retirement number is a dotted line labelled in a margin right of the plot, and the band's weak and strong edges are labelled there too, only when they are apart and off the axis; no label sits on a line. Saving stops at retirement; after that the balance pays spending and keeps its returns, and the page says so when it keeps growing. There is no kids lane under the chart, and no line saying the money runs out. A "Today's dollars | Future dollars" choice in the planner card's header switches the chart, the Retirement number and its breakdown ("Retirement number, in 2045 dollars", with the other figure beside it); today's dollars is the default. Yearly saving always shows in today's dollars and says so.
- There are no milestones; the chart and the yearly bars answer when the money gets where.
- There is no first-year withdrawal percentage.
- Spend a year starts at current yearly spending without loan payments (a house is planned as a cash purchase), and the ? beside it says so. When current spending differs, a link under the box applies it.
- Under the Spend heading, one visible line says amounts are entered in today's prices and raised by the inflation rate each year (not hidden behind a ?). Spend a year, Health cover, and the house each say under the box what the amount becomes in the year it's spent ("About $82,000 a year by 2050"). Spend a year also offers what the household spends now.
- Beside the figures on wide screens, the planner chart grows to the figures' height, so no empty band sits under it.
- Kids: a visible line says costs are per child, in today's prices. The two cost boxes stack on the left. The children are one list on the right, one same-shaped row each (name with age note, birth year, remove for planned children). Every child row is one line (name, birth year, remove), including on a phone; the list still scrolls after about three rows, with the same thin scrollbar as other cards and a fade at the bottom while more rows sit below. Add a planned child sits just under that list. Narrow screens stack the costs and the list.
- The planner works in today's money throughout: every amount entered (spending, kid and college costs, health cover, the house, other income, your own saving) is in today's prices and rises with inflation; growth becomes a real return. Ages count in whole years from the current age, so a part-year age never drops a child's year.
- The retirement number uses invested money (cash plus investments, less child accounts, editable, with net worth beside it), yearly spending, children, health cover until Medicare at 65 (default $20,000 a year), an optional house, and optional other income, tax, and a return after retiring. Lasting for good is priced with each year's money withdrawn at the start of the year, so the line stays flat. Money lasts forever is the default. A checkbox switches to spending it down, and only then asks for the age. Each child costs $25,000 a year through 17 and $70,000 a year for college from 18 through 21. Child-account balances reduce college. Inflation defaults to 3%.
- Boxes apply on Enter or leaving the box, and everything is saved across reloads. A save the server refuses or that fails says so in a toast where the person is working; nothing fails silently. Coming back with the browser's Back button reloads the planner, so it never shows (or saves over) older inputs. The planner holds up to 12 children, matching what household settings accept. Add a planned child sits just under the children list; at 12 it gives way to a note. Planned birth years run up to 40 years ahead. A box holding something unusable says why under it and is not applied. Optional amounts (other income, house) can be left blank.
- A ? beside Kids says both halves as short labelled lines, not sentences: "Before retiring: $X less saved (years)"; "After retiring: $Y set aside for their costs (years)", in the same dollars as the number; then the first college year's cost and child-account savings. Key dollar figures in these lines are bold and blue. The College box's help is one short line. Never say kids "add" money.
- "Saving a year (optional)" sits beside the Saving toward it bars; blank uses the estimate.
- The house's ? says what it adds to the number, including when that is nothing because the cost falls before retiring. The house price sits in Spend. On a wide Spend section, Spend it down is on the left of the same row as Buy the house the year I retire (checked by default, and it follows the slider). Narrow screens stack the two checkboxes. The boxes those checkboxes open sit on the next row, under the matching checkbox, so the checkboxes stay put: Spend it down by only when spending it down, and Buy the house at when the house is not bought the year you retire. Until that age is entered, the box says the house is not counted.
- The planner's inputs are grouped as Spend (invested, spending, health cover, house, and spend-down), with Saving a year beside the saving bars, an always-visible Assumptions (growth, inflation, return after retiring, tax on withdrawals, other income and when it starts), and Kids. No assumption is hidden behind a dropdown. Invested is rounded to the nearest $10,000 and follows cash and investments (less child accounts) until the household types its own figure; a link then offers the live total back.
- Property shows total equity with assets minus liabilities written underneath (and the share borrowed), then which values to update, or that every value is recent, with no separate real estate or vehicle pills. Home and vehicle boxes span the full width; the owner tag sits beside the name, and on phones Edit and Remove drop to their own row so the name shows.
- A home with a loan shows equity (worth, as-of date, owed, share borrowed), the monthly payment split into loan, taxes and insurance, and PMI, the interest still to pay with payoff date, when PMI can end, rent against the payment when rent is entered, an "Extra toward principal" box (capped at the loan balance, with a muted "e.g." hint), and the loan balance chart. The box saves; blank shows a worked example ("For example, $200 extra a month would save…"), and a saved amount adds a dashed "With extra payments" line and its key. A value over six months old (a year for vehicles) gets a nudge to update it. A vehicle worth less than its loan says so in red.
- Removing a home or vehicle asks first.
- Clicking anywhere on a retirement account's row opens its contribution history: this year and all time, a month-by-month chart, and every deposit newest first, marking the ones from pay. Manual accounts say contributions are not tracked. In the accounts table the Account and Holdings columns get the room; Holder and Type stay narrow. Holdings show a ticker when it is a real one, and the fund's name when the plan's id isn't (a 401(k) fund's code), and cash as "Cash".
- In the cash flow chart, retirement money is one income source, "Retirement accounts", like Salary. Clicking it lists each account by the same name the Retirement tab uses, with its bank's logo, and what went into it. Expanding an account lists each contribution with its date and the fund it bought, using the plan's own wording for the move. Expanding an RSU stock or an ESPP stock lists each vest or purchase with its date and the transaction's own wording. A breakdown opens with every line folded; a click opens one. Those rows do not open the transaction editor. To investments is not a bar of its own: what is left after spending is one "To savings/investments" bar, so the two sides always add up to the same total. Each side runs largest first with Other last.
- Take-home pay annualized includes every household member's paychecks, whether the bank labels them Paychecks or Salary. A deposit more than 20% off the usual amount, like a bonus, is left out, and the gap it leaves does not drop the regular paycheck.
- Cash deposited into a taxable brokerage with no matching outflow from any linked account (same amount within $1, within five days) came from an account Haus can't see. It counts as income ("Deposits from unlinked accounts") and goes straight to investments, and regular ones count as take-home pay. Deposits are only judged once every linked bank's history reaches their date; retirement and child accounts are judged separately (next line), and child accounts are left out.
- RSU vests and ESPP purchases arrive in the brokerage, not the bank, and are found by the broker's wording (conversion shares, RSU, vest, ESPP), never by company name. Vests count as income ("RSU vests") and flow to savings in the cash flow chart; they are net of shares withheld for tax. ESPP purchases count as income too ("ESPP purchases", the amount taken from pay, not the market value) and flow to investments; the cash credit that funds the buy is not counted again, and a purchase reported by both the plan and the brokerage counts once. Wording covers the common brokers (Fidelity, Schwab, E*Trade, Morgan Stanley) and employers' terms (RSU, GSU, release, ESPP, SPP), never one company. Vests are not paychecks, so they stay out of take-home pay. Dividends stay out of income. With Keep transactions on, vests and ESPP purchases are also saved, so they survive unlinking the brokerage.
- Money that goes from pay straight into a 401(k), 403(b), or HSA (the employee's share and the employer's match) counts as income ("Retirement accounts"; clicking it lists each account, and expanding an account lists each contribution and its date) and flows to investments, because no bank shows it. It is read from the plan's wording (contribution, CONTR, payroll, employer, deferral), not the plan's name. Rollovers, Roth conversions, moves between the household's accounts, dividends, and gains a fund exchange books as cash are not income. A plain deposit into any retirement account counts only when no linked account shows the same amount leaving within five days, so an IRA funded from a linked checking account is not counted twice.

## Insurance

- Insurance is the ID cards, large and clear: Health (per covered person: Medical, Vision, Dental, and Other), Vehicle, and Home tabs, each card a slot to upload, reupload, or remove. Other sits below those three, for images that are not a medical, vision, or dental card. It shows only once something is added; until then a quiet "Add other image" button takes its place. Adding one keeps the images already there, and each can be removed on its own. Removing the last image keeps the card and its premium. There are no coverage warnings or gap checks.
- A premium is optional. Each saved card has a quiet "Add premium" button (or its amount once set) that opens a Monthly or Yearly choice and an amount box; Enter saves and closes it, and removing the premium resets the choice to Monthly. Once any card shown on the page has a premium (a premium on a card that is not shown is not counted), a "Premiums a year" summary card sits above the tabs, with Health, Vehicle, and Home pills for the sections that have one.
- A saved card with no image says "No image yet" and offers Upload; an empty slot says "No card".

## Connections

- Connections opens with one status line: what needs relinking, what hasn't synced in two days, or that all connections are working. Relink is quiet on healthy connections and the main button on broken ones.
- Each institution lists its accounts in a table: name without the institution repeated, type and last four, balance (debts negative and grey), who it belongs to, and tax treatment (Taxable, Traditional IRA, 401(k), 403(b), Roth IRA, HSA, 529 college, Custodial, Trump Account) for investment accounts. Phones put the balance on the account's second line and stack both choices under it with small labels. A change the server refuses says so.
- Without Plaid keys the page says bank linking isn't set up, keeps the setup detail behind a "?", and disables Add institution. With no connections it shows the same centered empty state as other pages.

## Insights

- Insights opens with a Checkup card: how many measures need acting on, watching, or are on track, income and spending a year (the last three months x4, the same figures the savings rate uses) and the savings rate, and a numbered "Do first" list of the three next steps worth the most. With nothing to do it says so in green.
- Below it, one card per measure, act first, then watch, on track, and for reference. Each card has its area, a status chip, the title with a "?" for the working, the figure colored by status, a meter where there is a target, one sentence saying what to do next, and a link to the page to do it on.
- Every meter uses one scale: the target tick sits two thirds along, with the target written under the bar ("Target 6 months", "Limit 30%", "Target $52,458 a year · you save $61,200").
- The emergency fund is measured in months of must-pay spending: every loan payment plus rent and utilities, groceries, medical, and transport, averaged over the last 90 days from the same flows as Spending (emergency-fund.ts). Insights and Goals use the same figure. On Insights the category list sits behind "Show breakdown"; Goals keeps it open. The card lists each must-pay category a month, the must-pay total, the 6-month buffer amount, cash on hand, and how far cash sits from that buffer, and its "?" gives the division in words.
- Measures are judged against fixed rules of thumb, not settings: a 6-month emergency fund, a 20% savings rate, housing and loan payments within 36% of take-home pay, and card use under 30%. Stock mix is for reference only. There is no single-company or concentration measure. Bond and treasury funds count as bonds.
- The retirement card shows the Retirement planner's own verdict with the same defaults, so the two never disagree. Retirement contributions show only once some are recorded this year. College compares child accounts with the college years still ahead at the planner's yearly cost. When the Retirement planner already pays for college from saving, the card says so and suggests moving that saving into a 529, rather than asking for more; otherwise it says what to save a month, grown at the planner's return after inflation. Crypto share is for reference, since there is no crypto target.
- Savings rate counts RSU vests and ESPP purchases at their 12-month average (times three for the window), and its working says so. Housing share divides by take-home pay, so it counts vests the same way but leaves out retirement contributions and ESPP purchases.
- Fees and interest charges under $200 a year stay "for reference" and out of Do first. Insights has no insurance measure.
- "Interest paid on debt each year" sums each loan and mortgage balance times its rate, assumes the balances and rates stay as they are with no compounding, and says so under the figure. Credit cards are left out, since a card paid off each statement costs nothing and the data cannot show which cards are paid off. $1,000 a year or more needs acting on; under $200 stays for reference.

## Goals

- Goals is a budget tracker. There are no custom savings goals. Every budgeted category is judged at today's budget amounts over the last three calendar months, this one included (budget-tracker.ts). Each month is budget minus spent: saved or over. The open month counts only the share of its budget the days so far allow, marked "so far". Net sums the three months: Ahead, Behind, or On budget within $1. The most behind category comes first.
- The summary card's figure is the net across all budgets, with "ahead" or "behind" in words. Under it: the months covered, and this month's spent of budget with days left. An "Edit budgets" button beside the Budget by month heading goes to the Budget card on Spending. The pills are Categories ahead, Categories behind, Most ahead, and Most behind.
- Wide screens show one table with the usual small-caps heads: Category, Budget / mo, three months, "Net, 3 months", Status, and an "All budgets" total row. Dollar figures show cents, never rounded. Phones show one small card per category and say "net, 3 mo" under it. With no budgets, a one-line empty state links to Spending; with no accounts linked it says budgets start once accounts are linked and links to Connections.
- Under "Staying on track": the emergency fund and retirement cards from Insights. There is no college card.
- Goals can be hidden in Settings like the other optional tabs; it starts shown, after Retirement.

- Crypto and Insurance start hidden. Retirement, Property, and Insights start shown. Enabling a tab inserts it at its default position unless it was dragged.
- Data section: "Auto label transfers" ("Automatically categorizes transactions as "Transfer" when money flows between connected accounts.") and "Store transaction history" ("Saves your transaction history directly in the app to bypass data limits set by certain banks connected through Plaid.").
- Under Store transaction history, show "Since <date>" for when it was first turned on. "Show saved transactions" lines up with the other data controls.
- Turning off Store transaction history asks for confirmation: "Warning: This permanently deletes your local transaction history. Turning this feature back on will not recover transactions that exceed your financial institution's download limits." Nothing else ever deletes stored history, including reloads, redeploys, and turning the feature off and on without confirming.
- Log out sits directly below the other settings, with no gap above it.
- Settings has two columns of about equal height: Household and Tabs on the left; Display and Data on the right; Privacy & session runs full width right beneath them. Each column stacks its own cards and the last card stretches, so both columns end level with no gap. A birthdate label uses the name, or "Your" / "Partner's" when the name is blank or a placeholder. There is no Targets card.
- The Spouse box is optional. Blank (or the old default "Two") means no spouse: the sidebar shows only the primary, owner choices drop Spouse and Joint (Joint items show under the primary), the spouse birthdate and the Retirement "Ages are" choice go away, and Insurance lists no spouse. Money already owned by the spouse stays visible, labelled "Second person".

Years run from 1900 to 40 years ahead, the same as the planner, so planned children fit. A bad year says why under the box when Save household is pressed.

## Working on Haus

- Review Aurin's requested changes on the real household, at `localhost:3000` when Aurin runs `npm run dev` or `localhost` (port 80) when Aurin runs `npm start`, logged in with the real password from `.env`. Never copy real screenshots, numbers, or names into the repo, commits, or pull requests.
- Before editing a feature, run `npm run shots -- before --real` if the real server is up (it finds port 3000 or 80). After the change, run `npm run shots -- after --real` and `npm run shots:diff -- before after`. Look only at pages that changed, including ones you did not mean to touch. Screenshots stay in `.grok/shots/` and never go in git.
- Use a test household for cases the real one cannot show. `npm run demo -- full 3001` starts one on port 3001 with the password `demo-household`. `empty` is a brand-new user; UX reviews use only `full` (3001) and `empty` (3002). `single` (one person) and `random` (an extreme household from a seed) exist for specific bugs. `npm run demo:seed -- full` resets the data. Stop the test servers when done.
- The nightly bug-finding automation runs `npm run nightly-check`. That builds a random extreme household, checks every page, and shuts the server down. Local feature work does not run it.
- Check the browser console and the dev server log after every change, and fix what they show.
- Any change to how a page looks or behaves passes `npm run ux` and the `ux-critic` subagent before it is reported done (see `CLAUDE.md` or `.cursor/rules/ux-review.mdc`, and `docs/ux-checklist.md`).
- A page view never waits on something it doesn't need: no fixed pauses unless a download actually happened, outside prices cached (15 minutes, including symbols with no data), and slow key derivation done once. Tabs open in well under a second on the dev server; if one takes seconds, profile it before adding features.
- Day to day, Haus runs as a built app (`npm run build`, then `npm start`); `npm run dev` is for changing code.
- Browser code works over plain HTTP from another computer at home, where browsers switch off HTTPS-only features: no `crypto.randomUUID` (use `clientId()`), clipboard, or `crypto.subtle` without a fallback. Check a change that adds or saves something from another device's address, not only `localhost`.
- A raw SQL insert fills every required column itself, including `updatedAt`; Prisma's `@updatedAt` gives the database no default.
- Do not start `npm run dev` or `next dev`. Use Aurin's server on port 3000 or 80. Never touch either port. A hook stops anything left on ports 3001–3009 when the turn ends.
- When Aurin corrects something, add or update a line in this file in the same change.
